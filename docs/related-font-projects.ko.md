# 관련 프로젝트와 폰트 조합 자료

확인일: 2026-09-11. 사용자가 오늘 작업 기록에 추가하도록 전달한 자료다.
웹에서 읽은 설명과 이번 Jetendard 빌드에서 직접 검증한 결과는 구분한다.

## font-moeum: 병합과 미리보기의 반복을 줄이는 도구

[GeekNews 소개글](https://news.hada.io/topic?id=31633)의 작성자는 Jetendard에서
아이디어를 얻어 원하는 영문·한글 조합을 직접 만드는 GUI를 개발했다고 설명한다.
이 글은 자간을 줄인 완성 폰트의 소개보다, 조합과 옵션을 빠르게 비교하는 도구의
소개에 가깝다. 댓글 두 개는 긍정적인 반응이며 별도의 자간 측정 결과는 없다.

[공식 저장소 README](https://github.com/johndoekim/font-moeum)에서 확인한 기능:

- 영문·한글 TTF 또는 정적 CFF OTF 두 개를 받아 TTF로 출력한다.
- 일반 모드는 전체 병합, 코딩 모드는 한글을 라틴 셀의 정수배(기본 2배)에 맞춘다.
- 코딩 모드에서 한글 배율·폭 배수·세로 위치·한자 포함·자모 조합을 조정한다.
- 결과를 FontFace API로 바로 미리 보고, 크기·줄높이는 CSS로 바꾼다.
- CFF 입력은 cu2qu 변환을 거치며 CFF2 가변 OTF는 지원하지 않는다.

이번 작업에 대한 해석: 설치와 재시작 없이 Cove와 Compact를 나란히 비교하는
미리보기는 유용한 후속 기능이다. 다만 CSS 미리보기의 크기 조절이 저장되는
폰트의 한글 배율 변경과 같은 것은 아니다. 기본 2:1 코딩 모드도 동일한 셀 제약을
가지므로, GUI라는 이유로 일반 터미널의 소수 셀 배치를 해결하지는 않는다.
실제 터미널의 커서·선택·박스 연결은 별도로 확인해야 한다.

이 저장소의 코드 실행·병합 결과·독립 가로/세로 배율 지원 여부는 검사하지 않았다.
위 기능 목록은 공식 README 기준이며, 현재 Jetendard 구현을 교체하지 않았다.

## 셈틀체: 고정폭 섞어짜기를 전제로 한 글자 설계

[텀블벅 공식 페이지](https://tumblbug.com/semteulche)는 셈틀체를 프로그래머용
고정폭 섞어짜기 한글글꼴로 소개한다. 표시된 펀딩 기간은 2022-07-20부터
2022-09-18까지이며 종료된 프로젝트다. 접근 가능한 페이지에서 상세 기획 본문과
현재 배포 파일의 메트릭까지 확인하지는 못했다.

[2022년 GeekNews 소개](https://news.hada.io/topic?id=7048)에는 한영 디자인의
조화, 셀 공간 활용, 좁은 장체, 여러 굵기와 기울임체, 리거처·Powerline 지원이
소개되어 있다. 이는 당시 소개 내용이며 최종 배포본 기능을 직접 검사한 결과는 아니다.
댓글은 한글 가독성과 장식적 형태에 대한 우려, 제작자의 이전 프로젝트 라이선스에
관한 논쟁을 포함한다. 주관적 평가를 자간 측정이나 셈틀체 자체의 라이선스 판정으로
바꿔 해석해서는 안 된다.

이번 작업에 대한 해석: 고정 셀에서 여백을 줄이면서 모양을 자연스럽게 유지하려면
기존 글자를 단순 확대하는 것뿐 아니라 획·속공간·좌우 여백을 함께 설계하는 접근도
가능하다. 셈틀체는 이런 목적을 가진 설계 사례로 참고할 수 있다. 다만 소개된
장체가 윤곽만 좁히는지 셀 advance도 바꾸는지 확인하지 못했으므로, 장체가 곧
현재보다 촘촘한 한글을 뜻한다고 단정할 수 없다.

폰트 원본이 없어 UPM, 한영 advance 비율, 실제 자간, CaskaydiaCove와의 굵기·높이
조화는 측정하지 않았다. 따라서 셈틀체가 공백 보정이나 1:2 제약을 해결했다는
근거로 사용하지 않는다. 병합용 원본으로 채택하려면 실제 파일과 사용 조건을
확인하는 별도 작업이 필요하다.

## 추가 블로그: 코딩 폰트 추천과 fallback 사례

[찬 데브랩 글](https://chan7ee.tistory.com/165)은 현재 2026년 코딩 폰트 비교와
설정 안내를 싣고, 부록에 과거 Bitstream Vera Sans Mono와 맑은 고딕을 합쳐 쓴
경험을 남겼다. 영문은 마음에 들지만 한글 대체 글꼴은 마음에 들지 않아 합성했다는
문제의식이 이번 작업과 연결된다. 최신 본문은 JetBrains Mono와 D2Coding의
fallback 조합도 제안한다. 과거 합성 파일의 배율·advance 측정값은 제시하지 않는다.

이 글의 순위나 제품 설명을 검증된 기술 사양으로 그대로 옮기지는 않았다.
특히 다음 항목은 구분할 필요가 있다.

- 글에서 소개한 `Pretendard Mono`는 확인한
  [Pretendard 공식 패밀리 목록](https://github.com/orioncactus/pretendard)에 없다.
  해당 이름의 별도 프로젝트가 있는지까지 확인하지 않았으므로, 공식 고정폭
  버전이 존재하고 한영 1:2를 보장한다는 근거로 사용하지 않는다.
- 여러 에디터가 모두 동일한 `fontFamily` 설정 문법을 사용한다는 설명은
  그대로 적용할 수 없다. 예를 들어
  [Zed 공식 설정](https://zed.dev/docs/reference/all-settings#buffer-font-family)은
  `buffer_font_family`를 사용한다. 앱별 공식 설정을 확인해야 한다.
- Cascadia Code와 리거처 없는 Cascadia Mono의 차이는
  [Microsoft 공식 저장소](https://github.com/microsoft/cascadia-code)로 확인할 수 있다.
  Nerd Fonts의 Cove/Mono 구분은 오늘의 앞선 조사와 함께 참고한다.

이번 작업에 대한 해석: fallback은 글리프를 어느 폰트에서 가져올지 선택하는
방법이다. fallback 목록을 지정하는 것만으로 원본 파일의 UPM·윤곽 배율·advance가
이번 합성 폰트와 같아지는 것은 아니다. 따라서 한글 15pt·영문 14pt에 해당하는
독립 배율이나 자간 축소가 자동 적용된다고 보지 않는다. 앱의 실제 배치 결과와
폰트 파일의 메트릭을 나눠 확인해야 한다. 블로그 첨부 폰트는 내려받거나 검사하지 않았다.
